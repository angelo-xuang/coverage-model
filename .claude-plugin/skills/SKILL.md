# Coverage Model — 个人投资估值模型

构建一个**个人可理解、可控制**的股权估值模型。核心哲学：**人做定性判断确认框架，AI做定量映射填充细节**。

## 工作流程总览

```
Phase 1: 数据拉取 → Phase 2: 背景呈现 → Phase 2.5: 估值逻辑确认 → Phase 3: 定性判断 → Phase 4: 建模执行 → Phase 5: 合理性检验 → Phase 6: Excel输出
```

每个Phase结束后必须暂停，向用户展示结果并确认后再进入下一Phase。

---

## Phase 1: 数据拉取

### 1.1 拉取5年财务数据（IS）

运行 `scripts/fetch_financials.py <ticker>`：

- 从 yfinance + SEC EDGAR 拉取近5年损益表数据
- 自动将 FY 映射为自然年（参见财年处理规则）
- 输出：Revenue, COGS, Gross Profit, OpEx, EBIT, Net Income, 关键 margins
- 自动检测公司地区和货币，输出对应语言和币种

### 1.2 拉取业务分部数据

运行 `scripts/fetch_segments.py <ticker>`：

- 优先从 SEC EDGAR 10-K 拉取分部收入 breakdown
- 备选：用 web_reader 抓取 stockanalysis.com 的 segment 数据
- 拉取近5年的分部趋势，不只看最新一年

### 1.3 拉取市场背景时间线

用 WebSearch 搜索：
- 该公司过去5年每年的关键事件和市场讨论热点
- 可比公司/类比对象的历史数据（增长率、市占率、利润率轨迹）
- 行业周期位置

### 1.4 拉取估值历史

从 yfinance 拉取：
- 近5年 PE ratio 轨迹
- 当前市值、股价
- 分析师一致预期（如有）

## Phase 2.5: 估值逻辑确认（关键环节）

**这是最重要的一个 Phase。在填假设数字之前，必须先确认估值逻辑框架本身是否合理。**

### 2.5.1 确认收入构成拆解方式

不同类型的公司，收入拆解方式不同。AI 需要先呈现一个拆解框架，让用户确认：

**框架模板（根据公司类型选择）**

| 公司类型 | 收入拆解公式 | 适用场景 |
|----------|--------------|----------|
| **平台型（NVIDIA）** | 收入 = TAM × 可触达率 × 市占率 | 行业集中度高，公司有明确的市场定位 |
| **垂直型（Google）** | 收入 = Σ(各分部TAM × 各分部市占率) | 多业务线，各分部独立增长 |
| **用户驱动型（Netflix）** | 收入 = 用户数 × ARPU | 订阅制、SaaS、流媒体 |
| **产品驱动型（Apple）** | 收入 = 硬件收入 + 服务收入 | 硬件+生态组合 |
| **交易驱动型（券商）** | 收入 = 交易量 × 收费率 | 金融中介、电商平台 |

AI 需要根据公司业务特性，选择最合适的拆解方式，并向用户解释为什么。

### 2.5.2 定义每个乘数

以 NVIDIA 为例，AI 需要向用户展示：

```
【NVIDIA 收入拆解框架】

收入 = AIDC CapEx × NVDA可触达率 × NVDA市占率

┌─────────────────────────────────────────────────────────────┐
│ 第一个乘数：AIDC CapEx（全球数据中心AI加速计算资本支出）      │
│ ───────────────────────────────────────────────────────────│
│ 定义：全球各大云厂商、企业为AI训练/推理投入的GPU/加速器采购额 │
│ 数据来源：各云厂商CapEx公告、Gartner/IDC行业报告             │
│ 2023A: ~$30B                                                │
│ 2024A: ~$45B                                                │
│ 2025A: ~$65B（估算）                                        │
│                                                             │
│ 这个乘数决定了"天花板有多高"                                │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 第二个乘数：NVDA可触达率（NVDA能参与的市场比例）             │
│ ───────────────────────────────────────────────────────────│
│ 定义：AIDC CapEx中，GPU加速计算部分的占比                    │
│ 逻辑：AIDC CapEx 包含 GPU + 网络 + 存储 + 其他              │
│      NVDA 只能拿到 GPU 部分（以及部分网络 InfiniBand）       │
│ 历史估算：约 60-70%（GPU是AI CapEx的核心）                   │
│                                                             │
│ 这个乘数决定了"NVDA能吃多大的蛋糕"                          │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 第三个乘数：NVDA市占率（在GPU市场的份额）                    │
│ ───────────────────────────────────────────────────────────│
│ 定义：NVDA 在可触达市场（GPU加速计算）中的份额               │
│ 历史：2023A ~90%, 2024A ~88%, 2025A ~85%（AMD竞争加剧）     │
│ 数据来源：公司财报分部数据、行业分析报告                     │
│                                                             │
│ 这个乘数决定了"NVDA在蛋糕中能切多少"                        │
└─────────────────────────────────────────────────────────────┘

最终：收入 = $65B × 65% × 85% ≈ $36B（2025A估算）
实际：NVDA 2025A 数据中心收入 = $XXB（对比验证）
```

### 2.5.3 展示历史乘数轨迹

不只是看数字，还要看**每个乘数的历史变化趋势**：

```
【NVIDIA 历史乘数轨迹】

年份    AIDC CapEx    NVDA可触达率    NVDA市占率    推算收入    实际收入    差异
2021A   $15B         55%            80%           $6.6B      $XXB       ±XX%
2022A   $25B         60%            85%           $12.8B     $XXB       ±XX%
2023A   $30B         65%            90%           $17.6B     $XXB       ±XX%
2024A   $45B         65%            88%           $25.7B     $XXB       ±XX%
2025A   $65B         65%            85%           $36.1B     $XXB       ±XX%

观察：
- AIDC CapEx：2022-2025年CAGR ~37%，爆发式增长
- 可触达率：从55%升至65%，AI CapEx越来越集中在GPU
- 市占率：从80%升至90%再回落至85%，AMD竞争开始显现
- 推算与实际差异：±XX%，说明框架基本合理
```

### 2.5.4 用户确认三个关键点

AI 需要向用户提出三个问题，逐一确认：

**问题 1：拆解框架是否合理？**
> "您认为'收入 = AIDC CapEx × 可触达率 × 市占率'这个拆解方式，是否能准确反映 NVDA 的收入驱动因素？有没有遗漏的关键乘数？"

用户可以：
- 同意该框架
- 建议添加/修改乘数（如加上"ASP变化"或"产品结构权重"）
- 提出完全不同的拆解方式

**问题 2：每个乘数的定义是否准确？**
> "我对每个乘数的定义如下，您认为是否准确？"
> - AIDC CapEx = 全球AI数据中心资本支出
> - 可触达率 = NVDA能参与的市场比例（GPU部分占比）
> - 市占率 = NVDA在GPU市场的份额

**问题 3：历史趋势是否符合直觉？**
> "从历史数据看，AIDC CapEx 爆发增长、可触达率上升、市占率近期略有下滑。这个趋势是否符合您对行业的理解？"

### 2.5.5 不同公司的定制框架

AI 需要根据公司类型，选择合适的框架模板：

**Google (GOOGL) 框架示例**

```
收入 = 数字广告收入 + 云服务收入 + 其他收入

数字广告收入 = 全球数字广告市场 × Google广告市占率
云服务收入 = 全球云市场 × Google Cloud市占率
其他收入 = YouTube订阅 + Play商店 + 硬件

问题：
1. 是否应该把广告和云分开预测？（建议：是的，两者增长逻辑不同）
2. "全球数字广告市场"的边界是什么？（搜索+展示+视频？）
3. Google Cloud 市占率应该用什么口径？（按收入还是按算力？）
```

**Netflix 框架示例**

```
收入 = 全球流媒体用户数 × ARPU

全球流媒体用户数 = 发达市场渗透率 × 发达市场人口 + 新兴市场渗透率 × 新兴市场人口
ARPU = 基础订阅价 × 基础用户占比 + 高级订阅价 × 高级用户占比

问题：
1. 用户增长应该拆成发达市场和新兴市场吗？
2. ARPU变化主要来自价格调整还是用户结构变化？
```

### 2.5.6 框架确认后的输出

确认后，AI 输出一个结构化的"估值逻辑备忘录"：

```
【估值逻辑备忘录 — NVIDIA】

已确认的拆解框架：
收入 = AIDC CapEx × NVDA可触达率 × NVDA市占率

乘数定义：
1. AIDC CapEx: 全球AI数据中心资本支出，数据来源=云厂商CapEx公告+IDC报告
2. 可触达率: GPU部分占AIDC CapEx的比例，历史范围=55%-65%
3. 市占率: NVDA在GPU市场的份额，历史范围=80%-90%

历史验证：
框架推算与实际收入差异 ±10%，框架基本合理

下一步：
进入 Phase 3，对每个乘数的变化趋势做定性判断
```

**Phase 2.5 结束后必须暂停，等用户确认估值逻辑框架。如果没有确认，不能进入 Phase 3 假设设定。**

## Phase 3: 定性判断（基于确认的框架）

**Phase 3 是对 Phase 2.5 确认的每个乘数做趋势判断，而不是对抽象维度做判断。**

### 3.1 对每个乘数逐一讨论

以 NVIDIA 框架为例，讨论的是：

| 乘数 | 判断维度 | 判断选项 | 影响什么 |
|------|----------|----------|----------|
| **AIDC CapEx** | 行业增长阶段 | 起爆期/主升浪/成熟期 | TAM增速假设 |
| **可触达率** | 技术渗透方向 | GPU占比上升/持平/下降 | 可触达率路径 |
| **市占率** | 竞争格局变化 | 扩张/维持/收缩 | 市占率路径 |
| **利润率** | 盈利能力趋势 | 扩张/维持/收缩 | 毛利率/费用率 |
| **估值** | PE水平判断 | 高估/合理/低估 | 目标PE |

### 3.2 AI 先呈现证据和初步判断

对每个乘数：
1. 历史数据说明了什么趋势
2. 可比公司的类比证据
3. AI的初步倾向（附置信度）
4. 存在的不确定性

### 3.3 讨论过程

对每个乘数：
1. AI先说："我看到的证据是X，类比Y公司的轨迹是Z，我的初步判断是..."
2. 用户回应：可以同意、修正、或提供新视角
3. 达成共识后锁定该乘数的趋势判断

### 3.4 三情景自动推导

用户只需要确定 **Base case** 的判断，系统自动推导：

- **Bull case**: 每个乘数取乐观方向（CapEx增速更高、可触达率上升、市占率扩张、利润率更高、PE更高）
- **Bear case**: 每个乘数取保守方向

推导规则详见 [references/methodology.md](references/methodology.md)。

**Phase 3 结束后暂停，确认所有乘数的Base判断。**

## Phase 4: 建模执行

### 4.1 定性→定量映射

根据 Phase 3 的判断，将定性判断转化为具体数值：

以 NVIDIA 为例：
- AIDC CapEx "主升浪" → 未来3年CAGR 30%，后3年20%，后4年10%
- 可触达率 "持平" → 维持 65%
- 市占率 "收缩" → 从85%逐年降至70%
- 利润率 "维持" → 毛利率70%，费用率15%
- 估值 "合理" → 目标PE 25x

每个数值都需要注明**来源/推导依据**（填入 Excel 假设表的 G 列）。

### 4.2 构建预测

使用 Phase 2.5 确认的框架：

```
AIDC CapEx × NVDA可触达率 × NVDA市占率 = 收入
收入 × 毛利率 = 毛利
毛利 - 费用 = EBIT
EBIT × (1-税率) = 净利润
净利润 × 目标PE = 隐含市值
隐含市值 ÷ 股份数 = 隐含股价
```

### 4.3 三情景并列

Bear / Base / Bull 三个完整的假设块和预测列，通过下拉切换查看。

## Phase 5: 合理性检验

运行3层验证，详见 [references/sanity-checks.md](references/sanity-checks.md)：

1. **内部逻辑验证**：每个情景内增速递减、利润率在合理范围、增长率不超过物理极限
2. **跨情景排序**：Bull > Base > Bear，且差距合理（不是数量级差异）
3. **外部基准对比**：与可比公司历史轨迹、行业增速、市场共识比较

向用户展示验证结果，标记任何异常。**如果有异常，讨论是否需要调整。**

## 财年（FY）处理规则

### 核心原则

**不能简单地把"FY减一"当年自然年。** 必须先查看公司对财年的具体定义。

### 处理流程

1. **获取 FY 定义**：从 yfinance `fiscalYearEnd` 字段和实际财报日期推断
2. **建立映射表**：对每个具体财报日期做精确映射（参见 `scripts/fetch_financials.py` 中的 `analyze_fiscal_year` 函数）
3. **生成说明**：在 Excel 中增加"财年信息"工作表，详细列出每个 FY 对应的自然年

### 常见情况

| FY 结束月份 | 映射规则 | 示例 |
|------------|----------|------|
| 12月 | FY = 自然年，直接使用 | Google FY2024 = 2024A |
| 1-6月 | FY的大部分经营活动在**上一个**自然年 | NVIDIA FY2026(ending Jan) = 2025A |
| 7-11月 | FY的大部分经营活动在**当年** | Apple FY2024(ending Sep) = 2024A |

### Excel 财年信息表

生成的 Excel 包含一个独立的"Fiscal Year Info"工作表，内容：
- FY 结束月份和日期
- 是否与自然年一致
- 映射规则说明
- 每个财报日期 → FY标签 → 自然年 的对应表
- 完整的注意事项
